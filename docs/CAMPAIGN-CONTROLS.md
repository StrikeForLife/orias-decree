# 戰役操作與冒險須知

本文件記錄戰役操作、冒險須知與後續介面調整；正式 migration 及發布透過獨立流程執行。

## 使用方式

| 項目 | 行為 |
|---|---|
| 傷口結算 | 待結算傷口扣血成功後，播放與直接受傷相同的震動及資源欄紅光；止傷不播放受傷動畫。重繪時保留資源欄捲動位置。 |
| 祈禱 | 點選祈禱後開啟信仰卡橫列，顯示角色目前的信仰、圖像、引言及效果。選定後以頁內按鈕消耗 1 意志，不使用瀏覽器確認彈窗。祈禱記錄成功後播放火花及光環；最後一點意志亦可播放。重送同一操作不重播；系統「減少動態效果」設定會停用動畫。 |
| 武器與信仰 | 在我的角色按「調整武器／信仰」。武器依主武器／重型武器／副武器／非武器分頁，左欄加入、右欄調整數量或移除，同款可攜帶多把。信仰以沿用典籍神像的卡片切換，已選誓約另有摘要；可選多個信仰。 |
| 冒險須知 | 典籍新增「冒險須知」，可搜尋並展開 10 篇玩法／故事資訊。網站擁有者在典藏管理室的同名分類新增、修改、封存或復原。 |
| 我的角色 | 玩家選單只列出本人角色；沒有角色時顯示空狀態。隊伍仍能閱讀同行者公開卡。當前戰役 DM 的角色選單保留全隊。 |
| 建角 | 職業、法源道及出身使用單選卡片，保留原配色與關聯範圍，可用方向鍵選擇。重選介面沿用卡片及 DM 鎖定條件。六屬性沿用主頁六種配色；候選及已選法術可滑鼠停留或鍵盤聚焦，在左側預覽完整描述。核心法術可預覽但不可取消。主頁標籤仍以點選閱讀。 |
| 重新載入 | 操作按鈕整合於同一列的紋章工具列，窄螢幕可橫向捲動。重新載入按鈕顯示載入圖示，期間禁止重複點擊；完成或失敗時透過通知及可存取的狀態訊息公告。 |
| DM 資源調整 | DM 管理以成員頁籤切換，每個角色有生命／意志／等級滑桿，切換時保留未儲存草稿。生命可為負數，生命與意志調整不得超過角色上限；後端同樣驗證。舊有超上限數值不因開啟管理室或修改許可而改寫。 |

資源調整沿用 operation ID、CAS、重送去重及條件式撤銷記錄。裝備／信仰修改檢查角色版本並留下操作記錄；成功後會令較早的資源撤銷失效，避免跨越其他修改。後端重新核對擁有權、DM 權限與當前戰役，前端選單過濾不是唯一保護。

新取得的武器／信仰必須存在、未封存且未明確停用。既有停用裝備可保留、減少或移除，不能增加數量。武器總數最多 1000、不同武器最多 100 種、信仰最多 20 個，避免失控的請求及回應。大批裝備使用一次查詢與交易內 JSON 參照驗證，不依每個項目各發一個 D1 請求。

## CSV 與文字資料

來源為使用者提供的 `info sheet.csv`。`system_id` 保留，`name` 對應 `Name`，`content` 對應 `Content`；CSV 中的字面 `\n` 轉為換行，其餘措辭、錯字及公式維持原文。可審查的內容在 `live/content/archive-info.json`，初始資料寫入 0004 migration。

CSV 的法術難度文字使用「智慧」，現行計算使用 Intelligence（智力）；其他歷史措辭也可能與目前介面用語不同。這次只匯入資訊，不依 CSV 重寫規則或重新計算角色。內容之後可由擁有者在典藏管理室修訂。所有內容均作純文字顯示，不執行 HTML 或文件內指令。

## 新 migration 與回退

新增 `live/migrations/0004_campaign_controls.sql`，0001–0003 保持原樣：

- 在既有 `character_weapons` 加入 `quantity`，原有每一筆關聯預設為 1，不改角色／典籍 ID。
- 新增明確欄位的 `archive_info`（ID、名稱、內容、排序、版本與封存狀態），匯入 10 篇資訊。資訊不放回 definitions JSON。
- 原 sheet/state、角色數值／版本、筆記及 0003 的回退快照不變。

先在隔離副本套用及核對資料，再由管理者分開手動套用正式 0004，最後發布新 Worker。不要再次套用 0003、重跑 seed 或重新匯入玩家資料。新版 Worker 需要 0004，既有發布 schema gate 會阻止漏套 migration 的部署。

若 0004 失敗，停止部署並確認交易回滾；不要刪 migration 記錄或手動拆成無保護的部分寫入。若程式需回退，保留 0004、數量及資訊資料，使用經確認相容的 Worker deployment；舊介面會忽略數量／資訊功能，資料仍保留。不要刪 quantity 或 archive_info 以配合舊程式，嚴格 schema gate 也不能繞過。

## 驗證

一般檢查不需要瀏覽器套件：

```sh
npm run format:check
npm test
npm run build:live
```

API 回歸涵蓋數量及多信仰、越權與停用條目、交易內引用／權限競態、D1 查詢預算、版本衝突、DM 調整／重送／撤銷、CSV 內容及擁有者編輯／封存／復原、資料保留、傷口／祈禱與減少動態效果。

額外可執行本機整合檢查（僅虛構資料，不讀正式設定）：

```sh
# 需要已安裝的 Playwright 及 Chromium；可用 CHROMIUM_PATH 指定瀏覽器
node live/test/gameplay-ui.qa.mjs
# 需要已安裝的 Wrangler 4；非一般 node_modules 路徑可用 WRANGLER_MODULE_ROOT 指定
node live/test/campaign-d1.qa.mjs
```

Playwright 檢查實際連到同一 Worker 的本機合成資料站，測試所有新增介面、資訊文字的 HTML 跳脫、角色選單、失敗載入、鍵盤預覽及減少動態效果，截圖放在 `.runtime/gameplay-ui/`。D1 檢查使用本機 workerd／Miniflare、同一 migrations 與 API，驗證 SQL、資料交易及完整性。測試登入入口只存在測試 fixture，不會被 build 收進正式靜態資產或 Worker。

## 介面精修驗證

角色原生選單及展開選項使用明確的深色底與淺色字，配合五種主題。信仰區進場、神像懸停、選取／解除及已選標記使用動畫回饋；選擇立即更新本頁，仍須按儲存才寫入伺服器。系統減少動態效果設定會停用這些動畫。

`node live/test/ui-refinement.qa.mjs` 使用額外的合成選項測試可見的動畫畫格與火花、同列工具列、卡片／方向鍵／實際建角 payload、跨武器頁籤的數量保存、信仰神像與已選摘要、窄螢幕溢出及減少動態效果。截圖位於 `.runtime/ui-refinement/`。本次介面精修不需要新 migration，也不改後端 API 或正式資料。

### 正規化 trigger 與動畫回應

D1 的 `meta.changes` 包含正規化 trigger 的寫入；一次角色更新可能回報多於 1 筆。資源 CAS 以大於 0 判定本次成功，零才表示沒有更新。SQL `changes()` 仍維持「直接修改的筆數」語義，操作記錄、去重及撤銷交易不變。首次成功不標記 `replayed`，真正重送的操作才回傳 `replayed: true`，讓前端正確決定是否播放動畫。

本機 SQLite adapter 的 metadata 現在也包含 trigger 寫入，避免開發／瀏覽器測試掩蓋 D1 差異。`resource-replay.test.mjs` 及本機 workerd/D1 檢查涵蓋受傷、傷口結算、祈禱的首次／重送回應；介面檢查另加入 API 延遲。本修正不需 migration，不重算或改寫舊角色。

## 祈禱與 DM 管理

- 祈禱只列角色現有信仰；沒有指定信仰的舊角色可向自身意志祈禱，效果由 DM 裁定。選卡、取消均不消耗資源，按確認才記錄 1 點意志。魅力 DC 9 與失敗亦消耗的規則不變。選擇的信仰 ID 記入操作紀錄，後端驗證其屬於目前角色；舊 API 未帶 ID 的請求仍可用。
- 未確認的祈禱重試沿用 operation ID，不會因回應中斷重複扣除。儲存期間關閉或切換視窗，不會把完成訊息寫入另一個視窗。
- 信仰神像懸停僅放大，不旋轉；選取時播放火花，以勾號、實色標記與邊框區別已選。尊重減少動態效果。
- DM 成員頁籤保留各自的本頁草稿；生命／意志和等級／許可分開儲存。僅明確更改等級才重新計算該角色上限，現值超過新上限時降低至新上限。沒有觸碰的舊資源值不因其他欄位的調整自動截斷。
- 全隊長休以單一交易補滿啟用戰役成員的生命與意志、清除待結算傷口、保留臨時生命。查詢數不隨成員增加；交易內重新核對 DM 權限、啟用戰役與角色版本，衝突時整批回滾。重試沿用同一操作 ID，不會覆蓋長休後新受的傷害。

本批無新 migration，沒有正式資料操作或部署。新增 `prayer-dm.test.mjs`、`prayer-console.qa.mjs`，並更新既有瀏覽器及 workerd/D1 回歸；截圖在 `.runtime/prayer-console/`。
